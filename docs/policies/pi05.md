# π0.5 YAM server setup

Karma's adapter targets the `robocurve/pi0.5-yam` checkpoint and the transforms
previously used by the local Inspect Robots example. Those transforms now live
in `servers/serve_pi05.py`; that checkout is not needed at runtime.

## GPU environment

Use a separate [OpenPI checkout](https://github.com/Physical-Intelligence/openpi)
at the reference revision `15a9616`. Keep the model environment off the robot
workstation's CPU-only LeRobot environment.

```bash
git clone https://github.com/Physical-Intelligence/openpi.git
cd openpi
git checkout 15a9616
git submodule update --init --recursive
uv sync
uv pip install json-numpy pillow
```

Place the downloaded checkpoint in a local directory with:

```text
pi05-yam/
  params/
  assets/yam-bimanual-merged/norm_stats.json
```

Use the checkpoint's immutable download revision and record it alongside the
server log. The adapter's architecture is `Pi0Config(pi05=True, action_horizon=16)`;
its asset ID is `yam-bimanual-merged`. A different checkpoint/configuration needs
matching transforms rather than renaming these directories.

## Launch

Copy Karma's `servers/` directory to the GPU host, or use a Karma checkout there.
From the OpenPI environment:

```bash
uv run --no-sync python /path/to/karma/servers/serve_pi05.py \
  --ckpt /path/to/pi05-yam --host 0.0.0.0 --port 8204 --num-steps 10
```

The initial warmup compiles JAX and may take minutes. The server listens only
after it succeeds. Check from the robot workstation:

```bash
curl http://GPU_HOST:8204/act
```

Set `server` in `configs/policies/pi05-yam.json` to that host and run
`karma policy doctor --policy-config ...` before starting an episode.

## Contract

State and actions are left six joints plus gripper, then right, in radians and
normalized 1=open grippers. Targets are absolute. Images map to OpenPI's
`base_0_rgb`, `left_wrist_0_rgb`, and `right_wrist_0_rgb`. The model's padded
32-dimensional output is reduced to the trained 14 robot dimensions by the
checkpoint-specific output transform.

Actions are 16-row chunks at 30 Hz. `--num-steps` is fixed when loading the model;
set the client profile to the same value. `inference_ms` measures execution time,
while `action_hz` describes cadence. This corrects the reference server's use of
`dt_ms` as a fixed 33.3 ms action period.

JPEG and raw RGB inputs are both supported by the common server. No gripper or
policy-frame conversion is added for this YAM checkpoint.

See the [common commands](README.md) for inference, rollout, HITL, and Viser.
GPU loading and physical performance must be verified on the deployment host;
the repository's fake-model tests do not run JAX inference.
